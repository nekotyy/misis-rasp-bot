# Фазы реализации миниаппа

Обновлено: 5 ноября 2026 года. Требования и критерии приёмки — в [плане](miniapp-development-plan.md), решение об устройстве — в [ADR 0001](adr/0001-miniapp-architecture.md) и [ADR 0002](adr/0002-schedule-archive-schema.md). Фаза считается готовой только после проверок и интеграции, а не по наличию отдельного модуля.

| Фаза | Содержание | Состояние |
| --- | --- | --- |
| 0. Аудит | Карта подписок, импорта, снимков и доставки; исходные контракты | Выполнен первоначальный аудит |
| 1. Основы дат и замен | Календарные границы, безопасное структурированное сравнение пар, тесты | В работе: реализованы отдельные модули дат и сравнения; архивная опора и API не подключены |
| 2. Архив | Миграция, безопасный возобновляемый backfill, обновление при принятии расписаний, хранение, проверки старой БД | В работе: добавлены схема и отдельная запись дней; backfill и подключение ещё не реализованы |
| 3. Аккаунты и подписки | Совместимая миграция, общие записи, несколько групп, синхронизация ботов и получателей | Не начата |
| 4. Авторизация и API | Проверка платформ, отзывные сессии, профиль, расписание, история и настройки | Не начата |
| 5. Оболочка | React, адаптеры платформ, навигация, темы и состояния ошибок | Не начата |
| 6. Данные расписания и история | Реальные данные, замены, группы и навигация по неделям | Не начата |
| 7. Профиль и связывание | Подписки, уведомления, настройки, подтверждение связи и отвязка | Не начата |
| 8. Запуск и приёмка | CI, Docker/nginx, инструкции, сквозные и реальные проверки в Telegram/VK | Не начата |

После каждого завершённого изменения обновлять состояние этой таблицы, ADR при изменении решений и документацию запуска при изменении поведения. Не отмечать фазу завершённой без её критериев из основного плана.
