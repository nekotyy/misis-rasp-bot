# Фазы реализации миниаппа

Обновлено: 5 ноября 2026 года. Требования и критерии приёмки — в [плане](miniapp-development-plan.md), решение об устройстве — в [ADR 0001](adr/0001-miniapp-architecture.md) и [ADR 0002](adr/0002-schedule-archive-schema.md). Фаза считается готовой только после проверок и интеграции, а не по наличию отдельного модуля.

| Фаза | Содержание | Состояние |
| --- | --- | --- |
| 0. Аудит | Карта подписок, импорта, снимков и доставки; исходные контракты | Выполнен первоначальный аудит |
| 1. Основы дат и замен | Календарные границы, безопасное структурированное сравнение пар, тесты | Выполнена: реализованы модули дат и диффа, изолированная опора и тесты |
| 2. Архив | Миграция, безопасный возобновляемый backfill, обновление при принятии расписаний, хранение, проверки старой БД | Выполнена: схема, возобновляемый backfill, маркеры проекций, единый путь фиксации снимков/архива, перенос архивных дней при промоушене источников, тесты старой БД |
| 3. Аккаунты и подписки | Совместимая миграция, общие записи, несколько групп, синхронизация ботов и получателей | Выполнена: схема accounts/identities/subscriptions, миграция 20261105_0007, AccountService, синхронизация с users и ботами TG/VK, расширение активных источников и дедупликация рассылки с раздельной изоляцией каналов, тесты test_accounts.py |
| 4. Авторизация и API | Проверка платформ, отзывные сессии, профиль, расписание, история и настройки | Выполнена: проверка Telegram initData (HMAC-SHA256) и VK launch params, отзывные сессии miniapp_sessions, DTO, REST API в miniapp_api (профиль, настройки, поиск групп, CRUD подписок, расписание 3 дней со структурированным diff, история за неделю с границами 3 месяцев, связывание/отвязка аккаунтов), тесты test_miniapp_api.py |
| 5. Оболочка | React, адаптеры платформ, навигация, темы и состояния ошибок | Выполнена: React 19 + TypeScript + Vite в miniapp_frontend, дизайн-система МИСИС (электрик блю #0541f0, жидкое стекло glassmorphism, шрифты Nekst и Raleway, векторные SVG/Lucide вместо эмодзи), Tailwind CSS, TanStack Query, React Router, PlatformAdapter (Telegram WebApp, VK Bridge, Mock), компоненты BottomNav, LessonCard (со статусами замен и аккордеоном деталей), DayView, LoadingSkeleton, ErrorState, страницы Расписание/История/Профиль, хуки useAuth, useTheme, usePlatform, Vitest тесты, успешный build |
| 6. Данные расписания и история | Реальные данные, замены, группы и навигация по неделям | Выполнена: расписание на 3 дня со структурированным diff (замены, переносы, отмены, кабинеты/преподаватели), переключение групп в шапке при нескольких подписках, пустые состояния с переходом к выбору групп, архив с недельной навигацией за 3 месяца и аккордеоном дней, тесты Schedule.test.tsx |
| 7. Профиль и связывание | Подписки, уведомления, настройки, подтверждение связи и отвязка | Выполнена: управление несколькими группами (добавление через поиск по каталогу, назначение основной группы, уведомления по группе, удаление), связывание аккаунтов Telegram и VK по одноразовому коду, отвязка платформ, переключатель темы, ползунок масштаба с мобильными пресетами и сбросом, тесты Profile.test.tsx |
| 8. Запуск и приёмка | CI, Docker/nginx, инструкции, сквозные и реальные проверки в Telegram/VK | Выполнена: Docker-контейнеры miniapp-api и miniapp-frontend, интеграция в docker-compose.yml, multi-stage Dockerfile фронтенда, Nginx-шаблон miniapp.conf.template для домена miniapp.opk.nekoty.ru:443 (HTTPS) с проксированием /api/ и безопасными CSP/frame-ancestors для Telegram WebApp и VK Mini App, документация в .env.example, полные пайплайны проверок Python и Frontend |

После каждого завершённого изменения обновлять состояние этой таблицы, ADR при изменении решений и документацию запуска при изменении поведения. Не отмечать фазу завершённой без её критериев из основного плана.
