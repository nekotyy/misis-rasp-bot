# ADR 0002: таблицы дневного архива и опор сравнения

Статус: принято для начальной схемы. Дата: 5 ноября 2026 года.

## Решение

`schedule_day_archive` хранит одну проекцию на ключ источника, дату и вариант недели. `schedule_day_references` отдельно хранит опоры `first_seen` и `day_start`: обновление текущего дня или baseline рассылки не должно незаметно заменять опору. Вариант `0` означает отсутствие варианта недели. Запись содержит JSON дня, признак полноты, происхождение, время наблюдения и записи и необязательный ID исходного снимка.

Ссылка на снимок не является внешним ключом: очистка технических снимков не должна удалять архивные данные. Даты и JSON проверяет будущий сервис записи; сама схема не превращает пустой день с неизвестной полнотой в подтверждённое отсутствие пар. Источник, способ определения свежести, атомарность обновления и правила заполнения опор реализуются и проверяются при подключении архива.

Миграция создаёт только пустые таблицы и индекс, не изменяя снимки или профили. Автоматический downgrade запрещён, поскольку удаление таблиц может уничтожить сохранённые дни. Общие резервные копии SQLite включают новые таблицы; перед миграцией необходимо сохранять согласованную копию БД. При возврате к прежнему коду таблицы сохраняются.

## Ограничения

На этом этапе таблицы не заполняются, backfill и защита его данных от очистки ещё не реализованы. Существующая очистка снимков продолжает работать и может удалить данные до backfill. Архив нельзя использовать для истории до внедрения этих механизмов; отсутствие записи не доказывает отсутствие занятий. Отдельный учёт подтверждённого перехода `group-pending` к постоянному источнику остаётся задачей интеграции.
